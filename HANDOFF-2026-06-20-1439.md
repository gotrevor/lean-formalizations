## ⚠️ Gotchas
- **macOS-side FD exhaustion on first-from-source full builds.** v4.31 splits each olean into 3 files
  (`.olean`/`.olean.private`/`.olean.server`), tripling open-file pressure; ~10–16 heavy leaf files
  compiling in parallel in the final wave (jobs ~8590–8620) on the bind-mounted `/Users/...` path exhaust
  the macOS host's file-sharing FD cap (the Linux VM's `ulimit -n`=1048576 is NOT the limit). Symptom:
  `failed to open file '…olean.private': Too many open files` on a **rotating** leaf set. **Spurious** —
  each file builds fine alone. This toolchain's `lake` has **no `-j`/`--jobs` flag**. Fix: build modules
  sequentially once to cache —
  `find src -name '*.lean' | sed 's#^src/##; s#\.lean$##; s#/#.#g' | while read m; do lake build "$m"; done`
  — then the full `lake build` is an all-cached replay (no spike). Re-running the plain build a few times
  also converges.
- Build output is noisy with pre-existing linter warnings (deprecated `push_neg`, `Set.diff`/`sdiff`,
  unused vars/simp args) — none are errors; look for "Build completed successfully".
