## 🧠 Context to carry forward

**The result.** For every odd prime `c`, every `P` with `c ∤ P`, and every integer `h`,
`V_(c^n)(P,−1) + h` is composite for infinitely many `n` — `L(c^n) + h` is the `P = 1` case.
Unconditional, no `Literature/` hypothesis.

**The one idea that made it work.** Traces have no Frobenius sign flip (phase 34's engine), so the
route is an *exact composition*: `V_(cm) = V_c(V_m, −1)` for odd `m`.  That plus a growth bound
pins the `c`-adic limit to an integer fixed point and then to `0`, contradicting `V ≡ P (mod c)`.
Everything algebraic reduces to **one** lemma, `trace_pow_eq_lucasV : (B^k).trace = lucasV B.trace
B.det k` for any 2×2 integer `B`, by `Nat.twoStepInduction` off explicit Cayley–Hamilton.
Composition, the doubling identity `V_(2m) = V_m² − 2(−1)^m`, and Frobenius are all instances.

**Three things worth remembering about how it went.**

1. *Frobenius needed no field extension.*  My first plan was `AdjoinRoot (X² − xX − 1)` over
   `ZMod c` + `add_pow_char` on the two roots — which drags in `Nontrivial` and injectivity of
   `algebraMap`, i.e. a degree/linear-independence argument (the expensive part of phase 34).
   **Abandoned in favour of**: `B = !![x,1;1,0]` and `B' = !![0,−1;−1,x]` *commute*, have the same
   trace `x` and det `−1`, and sum to `diagonal (fun _ => x)`.  `Commute.add_pow` +
   `Matrix.trace_sum` gives `2x^c = V_c + V_c + (c-divisible middle)`; `c` odd cancels the 2.
   Strictly shorter.  Prefer this for any future `tr(B^p) ≡ (tr B)^p` obligation.
2. *Monotonicity was the real hazard, not the number theory.*  `SharedConjecture.exists_trace_pow_congr`'s
   endgame ("bigger prime divides smaller") needs `t n < t (n+j)`, but for `P ≤ −1` the trace
   *alternates*.  I considered porting phase 33's iterated-return trick; **didn't need it** —
   `lucasV (−x) (−1) k = (−1)^k lucasV x (−1) k` means at odd `c^n` the whole sequence just flips
   sign, so `(P,h)` reduces to `(−P,−h)` through `Prime (−z) ↔ Prime z`.  The main argument then
   only ever runs at `P ≥ 1`, where `V_k` is strictly increasing from `k = 1`.
3. *The endgame has no case split on `h` at all* — cleaner than phases 32 and 34, which both
   hand-handled `h = 0, ±1`.  The filter at `n` and `n+1` gives `V(c^n) ≡ x_n` and
   `V(c^(n+1)) ≡ x_(n+1) (mod c^(n/2))` with `x_n ∈ {1−h, −1−h}`; `dvd_lucasV_sub` (the sequence is
   a polynomial in its first argument, so it respects congruences) turns composition into
   `c^(n/2) ∣ lucasV x_n (−1) c − x_(n+1)`.  If `x_n ≠ 0` then `|V_c(x_n)| ≥ |x_n|+3` while
   `|x_(n+1)| ≤ |x_n|+2`, so that difference is nonzero yet bounded by a constant in `c, h` —
   choose `n` past the bound and you force `x_n = 0`, hence `c ∣ V(c^n)`.

## ⚠️ Gotchas

- **`HANDOFF.md` at the repo root is stale** (it describes phase 15, the Schanuel work). Don't read
  it as current state and don't overwrite it; the repo's live scheme is the dated
  `HANDOFF-YYYY-MM-DD-*.md` files.
- `rw` with a `?k + 2` recursion equation inside a `succ` induction will happily match `k+1+1`
  instead of the `k+1+2` you meant, silently rewriting the wrong side.
  `simp only [lucasV_succ_succ] at h ⊢` (expand everything, then `nlinarith` on the two remaining
  atoms) is the reliable move.  `rw [show k+1+2 = (k+1)+2 from rfl, …]` is a no-op and does not help.
- `abs_add` is gone from this mathlib pin; it is `abs_add_le`.
- `Int.coe_nat_prime` is gone; use `Nat.prime_iff_prime_int.1`.
- `set x := … with hx` makes `x` a let-bound local, so `rcases h with rfl` on something `x` depends
  on fails with "invalid equality proof".  Derive the disjunction explicitly (`Or.inl (by rw [hx,
  hh])`) instead of substituting.
- Don't `simp` a goal containing `r • (1 : Matrix …)` with a broad simp set — it rewrites to a
  `Int.cast`-into-matrix form and you get unreadable `↑x 0 0` goals.  Either drive `Matrix.smul_apply`
  with `simp only`, or sidestep by using `Matrix.diagonal (fun _ => r)` and `Matrix.diagonal_pow` /
  `Matrix.trace_diagonal` (what I ended up doing).
