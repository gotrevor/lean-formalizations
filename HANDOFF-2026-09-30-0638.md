  at `n'` and `k = 1 + j n'` at `n`" — two probes. The actual content is that those two probes
  **land on the same index**: `n + (1 + j n')·j n = n + j n + j n·j n' = n' + (j n)·j n'`. Once

## ⚠️ Gotchas

- **`set F : Fin d → ℕ := fun i => … with hF` silently breaks `Finset` sums.** `set` folds the
  body into `Finset.univ.sum F`, which no longer matches the `∑ i, F i` form, so later
  `rw [← hF]` and `omega` both fail on goals that look identical. Fix: don't `set` the summand —
  write the expression out. Cost me two build cycles.
- **`omega` will not commute a product.** `Nat.div_mul_le_self n d` is stated as `n / d * d ≤ n`;
  phrasing the pigeonhole bound as `d * (n / d)` left `omega` staring at two unrelated atoms and
  it reported a bogus counterexample. State the bound as `n / d * d` and add `mul_comm` to the
  `simp [Finset.card_univ]` that produces it.
- ℕ-subtraction in `glCard_factor_eq`: `Nat.mul_sub`-style lemma names are a coin flip. The
  robust pattern is `obtain ⟨s, hs⟩ : ∃ s, p ^ (d - i) = s + 1`, then finish with
  `rw [hs', hpow, hr, Nat.add_sub_cancel]`.
