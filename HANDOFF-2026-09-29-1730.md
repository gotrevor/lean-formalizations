## 🧠 Context to carry forward

The thing a successor most needs to know, and it is *not* in the commit messages:

**The rank-0 positive test is degenerate, and that limits how much reassurance it gives.**
`leopoldt_of_rank_zero` is true for a reason weaker than it looks. Once unit rank is 0 every unit
is torsion, so the conjecture's own hypothesis — that `ε₁,…,ε_r` be multiplicatively independent
— cannot be satisfied by any *nonempty* family. The proof therefore concludes `r = 0` and the
conclusion `a = 0` is vacuous (`Fin 0 → ℤ_[p]` is a subsingleton). So the test confirms the
statement is not *accidentally false*; it does not confirm the statement *says* anything. I chose
to prove it anyway because that is exactly what the directive asked for, but the honest reading is
recorded in `PENDING_WORK.md` and should not be quietly upgraded to "Leopoldt is verified for ℚ".

**The negative test is the informative one and it is sharp.** `not_leopoldtNoIndep_rat` kills the
independence-free variant for *every* prime `p` with a single witness (`ε = −1`, `mₙ ≡ 2`,
`a = 2`), which is strong evidence the independence clause is load-bearing rather than decorative.
Taken together: the formulation's *hypotheses* are now tested, its *content* is not.

**Design note on `shiftedAlg_of_sharp`.** The header's prose argument has a gap I had to close in
Lean: the ℚ̄-relation `β₀₁·y₀ − β₀₀·y₁ = 0` is only *nontrivial* when `(β₀₀, β₀₁) ≠ (0,0)`, so the
proof case-splits. The degenerate branch is where `x₀ ≠ 0` (from independence of `x`) is used, to
push `x₀y₀ = 0` down to `y₀ = 0` and contradict independence of `y`. Don't try to collapse the
two branches; the relation genuinely vanishes in the second.

**Import hygiene.** `witness_not_algIndep`'s ℚ-independence half is a re-derivation of
`Schanuel.linearIndependent_one_ofReal`. I inlined it rather than importing
`NumberTheory/Transcendence/Schanuel.lean` into `SharpSixVariants.lean` — the latter sits in the
`Literature`-facing layer and I did not want to pull the Schanuel development in behind it. If a
successor wants to dedupe, lift that lemma into a shared low-level file instead of adding the import.

## ⚠️ Gotchas

- **`Units.rank K = 0 → IsOfFinOrder` is not a mathlib lemma.** I looked; `rank_eq_zero_iff_*`
  does not exist. Derive it from `exist_unique_eq_mul_prod` plus an `IsEmpty (Fin (rank K))`
  instance — the instance is what lets `simp` kill the dependently-typed product.
- **mathlib at this pin has no p-adic logarithm.** `Mathlib/NumberTheory/Padics/` has no
  `padicLog`/`logOneAdd`, and nothing develops the unit group of `adicCompletion`. This is the
  whole reason the Leopoldt *statement* was written in exponent-sequence form, and the whole
  reason the rank-1 test is walled off.
- **`push_neg` is deprecated** at this pin — it emits a deprecation warning suggesting
  `push Not`. I used `push Not`; match that in new code or the linter complains.
- Membership in `integralClosure ℚ ℂ` is *defeq* to `IsIntegral ℚ`, so the anonymous constructor
  `⟨X^2 - C 2, by monicity!, by simp [h2]⟩` works with no `mem_*` lemma.
