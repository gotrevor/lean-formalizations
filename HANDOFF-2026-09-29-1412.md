## 🧠 Context to carry forward

Three pieces of the mental model that are *not* obvious from the file and cost real thinking:

**1. Irrationality is a prerequisite, not a bonus.** `Roth1955` as stated in `Literature/` carries
an `Irrational α` hypothesis (correctly — the theorem is vacuous for rationals). So the
contradiction hypothesis `IsAlgebraic ℚ C` is not enough to invoke Roth; `irrational_champernowne`
had to be proved *first and independently*. It came from the same approximations: if `C = q` then
`(q − p_m/q_m)·q.den·champDen m` is a **nonzero integer**, giving `|q − p_m/q_m| ≥ 1/(q.den·D_m)`;
instantiating `m := q.den` contradicts `|C − p_m/q_m| ≤ 2·10^{−N_{m+1}}` because
`N_{m+1} − N_m ≈ 9m·10^m` dwarfs `log₁₀ D_m ≈ N_m + 2m + 2`.

**2. Strictness comes from a leading-term gap — this was the key structural insight.** I initially
expected to need a separate "the `p_m/q_m` are distinct" argument and a separate
"`C − p_m/q_m ≠ 0`" argument, both of which look fiddly. They collapse into one observation: the
geometric continuation `∑_{j≥0}(a+j)T^{−(j+1)}` **overshoots** `C`. Its first dropped term is
`10^{−N_{m+1}}`, while `C`'s next real term (the digits of `10^{m+1}`) is `10^{−N_{m+1}−1}` — one
decimal place smaller, because `10^{m+1}/10^{m+2} = 1/10`. Hence
`C − p_m/q_m ∈ [−2·10^{−N_{m+1}}, −(4/5)·10^{−N_{m+1}}]`: strictly negative, quantitatively.
Injectivity then falls out with no extra work (a repeat would force `4/5 ≤ 1/5`), and
`Set.infinite_range_of_injective` feeds Roth an infinite subset of its finite exceptional set.

**3. Approach abandoned: proving the reduced denominator divides `10^N`.** Reasoning about
`Rat.den` of a partial sum is miserable. Instead define the *integer* `prefixNum` (the number
`123…K`) by `prefixNum (K+1) = prefixNum K · 10^{len(K+1)} + (K+1)`, prove
`cpartial K = prefixNum K / 10^{digitsUpTo K}` by a one-line induction, and then `champApprox m` is
*literally* `champNum m / champDen m` with `champDen m = 10^{N_m}(10^{m+1}−1)²`. `Rat.den_dvd` +
`Rat.divInt_eq_div` gives the denominator bound for free. Reuse this pattern for any
digits-of-a-sequence constant.

**Slack in the estimate:** `champ_exponent` proves `3(N_m + 2m + 2) + 1 ≤ N_{m+1}`, so `δ = 1`
(exponent 3) works comfortably. The plant's numeric script said the true exponent is 16.2/15.0/13.4
for k=2,3,4, decreasing to Amou's 10 — so all the crude constants (`10/9`, `2`, `1/5`) have room.
Nothing here is tight; don't waste a lap sharpening them.

## ⚠️ Gotchas

- `rw [pow_add]` rewrites the **first** `10^(m+1)` it finds, including one in a *numerator*.
  Prepare the denominator as a separate `have … := by rw [← pow_mul, ← pow_add, ← pow_add]` and
  rewrite with that. Relatedly, `set X := …` only folds syntactic matches, so a rewrite that ran
  first silently defeats it — `set` before, or after a prepared `have`.
- Narrow grep filters on `lake build` output hide real errors: `omega could not prove the goal`
  doesn't contain the word "error" on the line you grep. **Grep for `error` and trust the
  pre-commit full build**, which is what caught two live failures this lap.
- `tsum_le_tsum` / `le_tsum` are `Summable.`-namespaced projections in this mathlib; the bare names
  resolve only for `ℝ≥0∞`. Same for `Summable.sum_add_tsum_nat_add`, `Summable.tsum_eq_zero_add`.
- `Rat.mul_den_eq_num q : q * q.den = q.num` — do not fight `Rat.num_div_den` + `field_simp`.
- `Int.floor_eq_iff` takes **no** positivity side-goal in this mathlib version.
- `decide` evaluates `digitsUpTo 10 = 11` and `prefixNum 10 = 12345678910` fine — no
  `native_decide` needed, consistent with the repo's `decide +kernel` standing decision.
