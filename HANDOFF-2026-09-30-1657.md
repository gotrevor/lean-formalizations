## ⚠️ Gotchas

- **`npowRec` on mathlib's `Matrix` is a performance trap.** `Matrix` is a function type, so
  `A ^ k` is a closure chain: ~0.1 s per unit of exponent under `native_decide`. Exponent 250 is
  free, 500 ≈ 60 s, 3256 ≈ 5 min. The fix in this file is `tribMatMod_593_pow_order`: factor
  `3256 = 8 · 11 · 37` and stage through **literal** `!![..]` matrices with `pow_mul` twice, so
  each `decide` sees a small power of a concrete matrix. Get the literal entries from a 10-line
  Python matrix-power script first.
- **`pkill -f <pattern>` from the Bash tool kills the tool's own shell** (the harness wrapper's
  cmdline contains your pattern). You get exit 144 and the *rest* of the compound command never
  runs — which looks like a file mysteriously failing to appear. Loop over `/proc/*/cmdline`
  instead. Same trap makes a `pgrep -f`-based `until` wait loop never terminate.
- `lake env lean <file>` is the fast iteration path here (10 s vs a `lake build` dependency
  replay); use `lake build` only for the final green gate.
